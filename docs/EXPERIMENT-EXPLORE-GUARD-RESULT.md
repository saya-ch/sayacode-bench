**noguard 组**

| 题 | rep | 工具 | 探索 | **编辑** | 模型调用 | 结果 |
|---|---|---:|---:|---:|---:|---|
| navidrome | 1 | 59 | 55 | **0** | 29 | 未通过 |

**结论**：noguard 组 4 个 trial **一次编辑都没有**（探索 18–55 次后直接结束）；guard 组 4 个 trial 全部动手（6–15 次编辑）。

**「0 编辑 → 0 通过」是必然的**：没有 patch 就不可能过验证器。所以这不是"护栏让题目变简单"，而是**护栏让模型有机会交卷**。

**护栏让 token 成本接近翻倍**——因为它把"读一会儿就放弃"变成了"读完还要改、改完还要验证"。这是真实权衡，不是免费的。

## 2. 机制：护栏到底做了什么

`ExploreBudgetMiddleware` 在本轮真人请求之后统计只读工具调用（`read_file`/`list_directory`/`grep_search`/`glob_search`/`analyze_project`）；达到 `read_budget`（本次 12）且**尚未写过文件**时，注入一条提醒：

> 你已经连续调用了 N 次只读工具……在长上下文任务里这个模式高度预示失败：有用的信息已经收集到了，继续读只会把它们稀释。这一轮请直接动手：1. 如果已经定位到需要改的文件，现在就做出修改；2. 如果确实还缺信息，请**明确说出缺什么**，然后只做一次最有针对性的读取。不要再来一轮大范围搜索。

三个安全阀：
- **写过文件就完全不再动作**（不打断正在推进的任务）
- 最多 nudge 2 次
- 默认 `explore_read_budget=None` **关闭**，须由画像显式开启

## 3. 必须说明的局限（不要过度解读）

| 局限 | 说明 |
|---|---|
| **n=2 题 / 4 trial** | 样本极小。通过率 3/4 vs 0/4 的 Fisher 精确 p ≈ 0.14，**不显著**。「有编辑 4/4 vs 0/4」是行为事实，不受验证器影响，但也只有 4 个观测 |
| **只覆盖原本空 patch 的 2 题** | 选的是"最容易被救"的题（选择偏差）。对 flipt-io「改错」型失败**没有证据表明有效** |
| **成本翻倍** | 是真实代价。若按 token 计价，需判断"多通过 3/4 题"值不值 2 倍成本 |
| **noguard 0/4 低于历史 2/4** | 可能是 run 间波动，也可能 3.2.8 其它改动（检索限流等）使"只读不写"倾向更重。**未归因**，需要更多重复 |
| **单次验证** | 没有第二批次复现。统计上它只是"信号"，不是"结论" |

## 4. 一个被纠正的误判（记录教训）

分析中我一度认为发现了新 bug：「noguard 有一次 `glob_search` 输出 132,008 字符，说明 20k 限流没生效」。

查审计上下文后发现是**误读**：

```
[167] tool.started    01a1b501-8837-...   glob_search   ← 内层 run（工具内部 glob_inner.invoke）
[168] tool.completed  01a1b501-8837-...   glob_search   132,008  ← 内层原始输出
[169] tool.completed  chatcmpl-tool-a086-...  glob_search   20,121  ← 模型实际收到（截断生效）
```

**`output_characters` 对内层 run 也记录**，132,008 是工具内部返回值，模型看到的是 20,121（20,000 + 截断提示 121 字符）。**限流正常**。

这是本项目第三次同类错误（前两次：`instance_` 前缀只看 `jobs/`、pilot 的 `reward.txt` 只在 `verify/jobs/`）。共同点：**只看字段名不看字段语义、只看一个目录不看另一个**。已记入坑库。

## 5. 下一步

| 优先级 | 动作 | 理由 |
|---|---|---|
| **P0** | 在**完整 6 题 × 2 重复**上跑 guard vs noguard | 当前只有 2 题，且是选择偏差最大的 2 题；需要看 4 题「原本通过」的题会不会被护栏**干扰**（这是主要风险） |
| **P1** | 若上面正向，做**预算扫描**（8 / 12 / 20）| 找性价比拐点，当前 12 是拍的 |
| **P1** | 查 `noguard 0/4` vs `历史 2/4` 是否是 3.2.8 引入的退化 | 如果是，说明除了护栏还有别的行为回归要修 |
| **P2** | 对 flipt-io 那种「改错」型失败单独诊断 | 护栏对这类无效，需另找机制（可能是定位精度问题） |

**关键风险**：护栏只对「不动手」有效。对「动手但改错」（flipt-io 2/2、navidrome r2）这类失败无证据有效，且提醒可能干扰原本正常的 trial。完整 6 题验证必须先看**有没有把原本通过的题搞坏**。
