# 工具并行度实验：加提示无效，反而变差（2026-11-09）

> **结论：在四个只读工具的 description 里加「可并行」提示，
> 平均工具/响应从 1.80 降到 1.72（-4.6%），只发 1 个的比例反而
> 从 58.8% 升到 66.8%，成本和延迟都上升。不上产品。**

| 项 | 值 |
|---|---|
| 假设 | 73% 的响应只发 1 个工具，是因为工具描述没提并行 |
| 变体 | 3.6.1，读/列/glob/grep 四个工具 description 各加一句要求 |
| 设计 | 6 题 × 2 重复 = 12 trial，对照组复用 `run-todo-compact`（同题集 3.3.0）|
| 主指标 | **平均每次响应的工具调用数**（连续量）|
| 分支 | `exp/tool-batching`（`d25974d`），未合并 |

---

## 1. 结果

| 指标 | 3.3.0 基线 | 3.6.1 加提示 | 变化 |
|---|---:|---:|---:|
| **平均工具/响应** | **1.80** | **1.72** | **-4.6%** |
| 中位工具/响应 | 1.00 | 1.00 | 0 |
| **只发 1 个的响应占比** | **58.8%** | **66.8%** | **+8.0pp** |
| 批量内只读工具均值 | 2.29 | 2.22 | -3.1% |
| 响应数 | 320 | 376 | +17.5% |
| 工具调用总数 | 576 | 646 | +12.2% |
| input tokens | 23,253,792 | 25,520,086 | **+9.7%** |
| output tokens | 280,505 | 335,735 | +19.7% |
| 墙钟中位 | 8.9 分钟 | **11.2 分钟** | **+2.4 分钟** |

**全部指标都朝坏的方向走。**

---

## 2. 改动内容

只在四个只读工具的 docstring 里各加一句**纯要求**（不写后果，按用户意见精简过）：

```
read_file        并行，多个互不依赖的文件应在同一轮响应里一起读。
list_directory   多个互不依赖的目录应在同一轮响应里一起列。
glob_search      Batching: independent calls can be issued together in one response.
grep_search      Batching: independent calls can be issued together in one response.
```

第一版写成了「逐个读会让整段对话被重复发送多次，既慢又贵」，用户指出
「工具描述不必说后果，只说要求也是可以的」，已按此精简后重新构建 wheel 再跑。

---

## 3. 为什么无效（三种可能，本实验无法区分）

1. **模型生成层面就是串行的**：一次响应里发几个 tool_call 由模型解码决定，
   description 里的提示动不了这一层。这解释了为什么加提示反而更差——
   多出来的文字干扰了原有判断，却没改变生成行为。
2. **样本太小**：n=12，-4.6% 可能只是波动。但方向是「更差」，不是「略好」，所以不像是噪声中的正向。
3. **提示词位置无效**：系统提示里那条「Batch every independent read-only call...」
   本来就没生效，把它复制到工具描述也没用。

## 4. 五轮干预的完整记录

| 轮次 | 干预 | 层面 | 主指标 | 结果 |
|---|---|---|---|---|
| 1 | `ExploreBudgetMiddleware` | 运行时中间件 | 空 patch 数 | 归零，但通过率不动 + 51 分钟长尾 |
| 2 | 系统提示精简 63%（v2）| 提示词 | 通过率 | 12 trial +8.3pp → **扩样本归零** |
| 3 | 影响面检查清单 | 提示词 | 覆盖率 | +6.6pp，但**通过率 +2.5pp、p=1.0** |
| 4 | （验证）强制 build | — | — | 模型本来就在跑 build（70% vs 69%），不需要 |
| 5 | **工具描述加并行提示** | **工具描述** | **工具并行度** | **-4.6%，更差** |

**五轮分别动了运行时、系统提示、工具描述；主指标分别用了通过率、
覆盖率、空 patch 数、工具并行度。全部无效。**

---

## 5. 结论

**SAYACODE 当前的能力边界不在「提示词写得够不够清楚」，也不在「行为缺不缺约束」。**

证据链：
- 模型会验证（通过的 trial 100% 跑过命令，失败的 79% 也跑了）
- 模型会努力（失败 trial 命令数中位 26 > 通过 16）
- 模型会自证（ansible-415e08 跑了 8 个自定义检查脚本）
- **加了明确的行为要求后，行为没变（本轮），或者变了对分数没影响（前几轮）**

剩下的可改空间只在**基础设施层**，不在模型行为层：

| 方向 | 依据 | 风险 |
|---|---|---|
| `DeltaChannel` 增量 checkpoint | checkpoints 合计 5.36GB，中位 80MB/文件 | Beta 特性，剪枝会断 delta 链 |
| 压缩 vhdx | vhdx 107GB，实际内容约 45GB | 需停 Docker |
| 减少上下文重复携带 | input:output = 70:1 | 依赖并行度，本轮证明改不动 |
