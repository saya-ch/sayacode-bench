## 3. 语义 diff：通过但 patch 与 gold 差异大的 top 10

- 方法：对每个 `reward=1` 的 trial，比较 `agent/model.patch` 的 `+++ b/` 文件集与 `gold_patch.diff` 文件集，Jaccard = 交集/并集；排除 26–27MB 的 `flipt-ee02b164` 重写型；参与计算 172 个通过 trial。
- **top 1–3（Jaccard 0.20–0.25）是「修改既有测试/快照后通过」**：
  - `codex-element-hq__element-web-9bf77963ee-r1`：改 3 个 `__snapshots__/*.snap`（`DeviceDetails-test.tsx.snap` **+156 行**）+ 2 个测试；
  - `codex-element-hq__element-web-772df30212-r2`：改 1 个 `.snap` + 1 个测试；
  - `codex-ansible__ansible-de01db08-r2`：改 `test/units/modules/test_pip.py`（+26 行）。
- **关键修正**：只有含 `.snap` 的 trial 有效（`.snap` 不被 verifier 重置）；纯改 `test_pip.py` / `*_test.go` 会被 reset，**不构成作弊**。详见 [TEST-EDIT-ANALYSIS](TEST-EDIT-ANALYSIS-20261102.md)。原分析「top 1–3 是改测试通过的直接证据」部分正确，须按快照/测试代码区分。
- **top 4–10（Jaccard = 0.25）是「agent 只改 1 个 src、gold 改 4 个」**：如 `ansible-fb144c44` 三 agent 都只改 1 文件、gold 改 4（含 changelog/docs），属正常最小修复，不是作弊。
- **结论**：不能用「patch 含测试文件」当作弊率；有效「改快照通过」仅 mini-swe 4 / Codex 3 / SAYACODE 0。

## 4. 成本-部分相关性

数据：`C:\sb\tmp\explore\analysis\raw.json` 的 partial / input_tokens / model_calls / duration；分「全部」与「仅失败 trial（reward≠1）」。

| agent | 组 | n | r(partial, tokens) | rho(partial, tokens) | r(partial, duration) |
|---|---|---|---|---|---|
| SAYACODE | all | 76 | −0.03 | −0.08 | −0.42 |
| SAYACODE | fail_only | 16 | **−0.33** | −0.29 | **−0.65** |
| mini-swe | all | 65 | −0.28 | −0.19 | −0.21 |
| mini-swe | fail_only | 9 | −0.36 | −0.03 | −0.05 |
| Codex | all | 79 | −0.06 | 0.08 | −0.25 |
| Codex | fail_only | 24 | −0.21 | −0.30 | −0.33 |

**结论**：
- **无正相关**：没有一个 agent 呈现「token 越多 partial 越高」。
- 仅失败 trial 内，多烧 token/时间与更高 partial **负相关**（SAYACODE r(duration) = −0.65），追加成本没换来更多 Required tests 通过。
- **因果不能反推**：更难的题既耗 token 又 partial 低，不能证明「省 token 能提高 partial」，只能否定「多花 token 能提升 partial」。
- 不可比项：mini-swe 仅覆盖 65/80、`usage_complete=false` 74 条、token 缺 15；fail_only 每组 9–24，Spearman 不稳，方向可参考、数值不外推。
