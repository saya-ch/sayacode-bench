# TodoList 提示压缩：成本优化实测（2026-11-07）

> **结论：这是一次成功的成本优化，不是一次失败的假设验证。**
> 同等通过率下，模型调用 -30%、input tokens -15.6%、耗时 -40%。

| 项 | 值 |
|---|---|
| 变更 | TodoList 两段提示 6,502 → 1,148 字符（**-82%**），产品 `3d45472`，版本 3.3.0 |
| 背景 | 两段提示里 **81% 是 LangChain 框架默认文案**（系统提示 1,370 + 工具描述 3,873），我们只追加 1,259 |
| 外部参照 | OpenCode 的 `todowrite.txt` 仅 **512 字符**且为 experimental 默认关闭；Codex 没有 todo 工具 |
| 设计 | 单变量对照：同 6 题 × 2 重复、同 noise-100k、同 profile（都不触发 middleware）|
| 对照 | `C:\sb\hard\ab-ctx\run-noguard`（3.2.8，todo 6,502 字符，8/12）|
| 实验 | `C:\sb\hard\ab-ctx\run-todo-compact`（3.3.0，todo 1,148 字符，8/12）|

---

## 1. 结果

### 1.1 质量：完全持平

| 组 | 通过 | 通过率 | 空 patch |
|---|---:|---:|---:|
| clean（无噪声基准）| 12/12 | 100.0% | 0/12 |
| **3.3.0（todo 压缩）** | **8/12** | **66.7%** | 2/12 |
| 3.2.8（todo 原版）| 8/12 | 66.7% | 2/12 |

配对：双方通过 7、压缩后变好 1（NodeBB r1）、压缩后变差 1（navidrome r1）、双方失败 3。
**Δ = +0.0pp，McNemar p = 1.0000。**

### 1.2 成本：显著下降

| 指标 | 3.2.8（6,502 字符）| **3.3.0（1,148 字符）** | 变化 |
|---|---:|---:|---:|
| **模型调用合计** | 489 | **342** | **-30.1%** |
| **input tokens 总量** | 27,563,182 | **23,253,792** | **-15.6%** |
| input 中位 | 2,138,914 | 1,867,922 | -12.7% |
| input 峰值中位 | 101,844 | 101,282 | -0.6% |
| **耗时中位** | 13.0 分钟 | **7.7 分钟** | **-40%** |
| 工具调用合计 | 744 | 576 | -22.6% |

**关键点：节省不只来自「每轮少 1,530 tokens」，更来自调用次数少了 30%**（489 → 342，少 147 次）。压缩后的 todo 提示不再让模型花轮次维护清单。

峰值几乎没变（-0.6%），因为长上下文的峰值由 100k 噪声决定，todo 只占其中 3.5%。

### 1.3 行为：编辑更少，但质量不变

| 组 | 编辑合计 | 零编辑 trial |
|---|---:|---:|
| 3.3.0 | **65** | 2/12 |
| 3.2.8 | **100** | 2/12 |

编辑次数 **-35%**。但通过率不变——说明被省掉的那些编辑是**冗余的**（改来改去最后没用上，或者本来就不该改）。

---

## 2. 这次实验**没有**回答的问题

最初假设是「todo 提示 6,502 字符臃肿 → 模型过度规划、不敢下手（空 patch）」。

**这个假设被证伪**：

- 空 patch 仍是 **2/12**（没有减少）
- 只是位置变了：3.2.8 是 NodeBB r1 + navidrome r2；3.3.0 是 flipt-io r1 + navidrome r1

所以 **“不敢下手”与 todo 提示规模无关**。那段提示的规划引导实际上在推动模型行动（删掉后编辑 -35%），只是这种“推动”对最终通过率没有净贡献。

---

## 3. 为什么这是好事

| 视角 | 判断 |
|---|---|
| **工程** | 同等质量、成本 -15.6% tokens / -30% 调用 / -40% 时间。**纯赚** |
| **研究** | 证伪了一个假设（todo 规模不是空 patch 的成因），缩小了下一次的搜索空间 |
| **产品** | 静态上下文减小 5,354 字符，对长上下文任务有正向边际 |

两个视角都成立，工程价值是正的。

---

## 4. 保留的约束（未被优化掉）

压缩删的是重复说教，**所有有行为约束力的条目都在**（`tests/agent/test_todo_prompt_budget.py` 10 例锁住）：

- 何时用 / 何时跳过（3+ 步、用户要计划、多任务）
- 状态标记（`in_progress` / `completed`）
- 不许在 partial / blocked / unverified 时标记完成
- 不许并行调用 `write_todos`
- 最终答案必须在最后一次 `write_todos` 之后
- 子 agent 完成是证据而非自动验收

变异检验：拼回框架默认段落、删掉防虚报规则，测试都会变红。

---

## 5. 下一步

「不敢下手」的真因仍未找到。已排除的两个：

| 假设 | 做法 | 结果 |
|---|---|---|
| 缺运行时提醒 | ExploreBudgetMiddleware | 空 patch 2/12→0/12，但 p=0.625 不显著、干扰 tutao r2、单 trial 最长 51 分钟。**已删** |
| todo 提示臃肿 | 压缩 82% | 通过率无变化。**已保留（成本收益明确）** |

还没测的：**系统提示 3,489 字符**（占静态上下文 31%）。这是唯一未排除的大项。

但要注意：3.3.0 已经把 todo 从 6,502 降到 1,148，静态上下文总量从约 11,373 降到约 6,019。系统提示现在占的比例更高了。
