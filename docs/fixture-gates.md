# 正式模型运行前的环境资格门禁

本流程先检查官方任务在固定本地环境是否可执行，再冻结模型实验子集。没有使用 Agent 成绩筛选题目，不修改官方评分，也不声称筛选后的结果代表完整公开榜单。

## 本次校准为何需要补门禁

同一已知 qutebrowser 校准题的固定补丁三次 pristine 重判均为 0，官方参考解三次也均为 0。六个新环境的原生证据一致：镜像 `sha256:cc0e0f503659eac82afb4f304e853c5a94ddd2aba834e62d3fd757fa6fba13e3`、amd64/Linux、1 CPU、4 GiB 内存；Docker 与 cgroup 限制一致。

官方参考解也出现 pytest AST 重写错误、测试收集失败和不同测试数量；因此这道 fixture 没有通过当前本地环境的资格检查，不能把这些失败归因于 SAYACODE。旧版一次 gold 通过与新三次 gold 失败说明单次预检不足；旧运行缺少同等原生 runtime 证据，不能倒推旧镜像摘要。具体上游镜像、依赖或本地运行时的根因仍未确定。

三次参考解通过也不是绝对稳定的证明，只是固定的可复现准入条件。原始所有 reward 保留。

## 固定条件

在任何正式开发或最终模型试验前，每个候选任务都执行：

1. 三次全新环境官方 oracle，全部正常结束、已确认判分且 reward=1。
2. 一次全新环境官方 nop，正常结束、已确认判分且 reward=0。
3. 四次都有可用原生 runtime，镜像、平台、请求资源与实际 Docker 限制一致。

固定三加一全跑，不因第一轮失败提前另抽分数，不运行到成功为止。异常和非零结果保存；只有已经保存的相同输入原生 job 或资格子记录可以恢复复用。未收尾原生 job 不以新名字静默重跑，证据不足会导致该次资格不通过。

门禁依据官方验证器的输出与原生环境观测，不增加新的任务功能评分器。nop 的官方拒绝可能来自缺失实现引起的导入或行为失败，不能把所有测试未收集都泛化为产品问题；原始日志用于区分已知框架故障和预期缺失实现。

## 确定性替补与分层

初始选样已经固定完整候选池 SHA、seed、开发／最终数量、资源／语言／类别／timeout 范围、校准修复组排除。资格脚本保留这些条件：

- 先完成当前选择版本中全部任务的固定资格检查，再集中排除失败任务的整个 fix 组。
- 使用同一个完整 catalog、seed 和原规则重新调用既有分层 selector。所有失败理由单独为 `fixture_qualification_failed`，不冒称校准题或功能难度排除。
- 原 selector 按仓库（SWE）或类别（TB）轮转；同层有候选时机械使用固定哈希顺序。某层实际耗尽时，原轮转自然在其余有容量的层继续分配，并公开最终各层数量与缺失层。
- 不因某一仓库近期失败而私自跳过剩余候选，不改 seed、降 N 或改评分器。若要另加每层预算，必须另行预注册，不能中途实施。
- 最多检查 64 个不同任务。已经完成资格的 ID 会缓存，重新出现在后续选择中不会重跑。达到上限或候选池不足时，结果明确 `complete=false`，不能把不足数量写成完整验收。
- 每开始一个尚未执行的新候选前，结果所在磁盘必须至少剩余 12 GiB。阈值写入 plan；不足时以 `insufficient_disk_headroom` 停止，未执行题不判失败、不排除其 fix 组，也不自动清理用户 Docker 镜像。

例如一整个仓库族可能持续失败而在 64 个总候选预算内尚未穷尽。此时流程可能无法填满原定 8 个 dev 和 24 个最终任务，必须报告预算耗尽，不将未经验证的同仓库任务宣称全部不可用。

## 命令与结果

```powershell
python scripts/qualify_fixtures.py --selection studies/primary-selection-v1.json --cache C:\sb\s --output C:\sb\r\primary-fixtures-v1 --oracle-repeats 3
```

开发／最终目标数量由 selection 推断，因此同一脚本也支持 TB 的 2 个环境校准候选与 12 个最终候选。不同基准分别运行、分别报告；脚本不读取题面或参考解内容，参考解只由官方 oracle 在环境中执行。

输出包含：

- `plan.json`：初始选择、完整池、脚本和执行实现身份，固定三加一、候选预算和原 seed/rules。
- `initial-selection.json`：初始文件原始字节。
- `selections/selection-*.json`：每次替补选择，不覆盖旧版本。
- `qualifications/`：每个候选的全部固定原生结果与资格判据。
- `jobs/`：独立官方 job、原始结果和 runtime 证据。
- `selection.json`：当前最终选择。
- `sanity.json`：兼容既有 `validate_preflight` 的门禁结果，只有全部目标都合格才 complete/passed。

新 output 拒绝覆盖其他计划。输入、脚本、执行实现和初始选择身份完全一致时可以恢复，已保存的同名 job 不会再次执行。中断位置不能改变替补策略：恢复先完成已保存的当前选择版本，再决定下一版。

冻结正式模型实验时必须使用本目录的最终 `selection.json` 和 `sanity.json`，同时保留原始完整池及排除记录。结果只能称为**固定本地协议下的环境资格子集**；不能称原 642 道题的均匀抽样，也不能将参考解失败率混入 Agent 解题成功率。
