## 2. 站得住的结论

1. **注入 ≈100k 无关上下文确实让 SAYACODE 退化**（100% → 58.3%，配对 5 退化 / 0 反转，题块 CI95 不含 0）。
2. **退化形态是「只读不写」**，不是「不会做」——同一批题在干净上下文下 12/12 全过。
3. **压缩 TodoList 提示是无损降本**：-82% 字符，通过率持平，时间 -40%、tokens -15.6%。
4. **系统提示的关键变量不是长度，是取向**：
   - v1 把字符砍 58% 却 `never` 一个没减（5→5），通过率反跌 8.4pp；
   - v2 砍 63%、`never` 归零、补上目标陈述/交付要求/动手驱动，12 trial 上高 8.3pp
  ——**但扩到 20 题后归零（65.0% vs 65.0%，Δ=0，p=1.0）**。
5. ~~v2 让空 patch 归零~~ ——**不成立**。12 trial 是 0/12，20 题是 2/20，与 main 相同。

## 4. 我做错的方法（按严重度）

| # | 错误 | 后果 | 谁发现 |
|---|---|---|---|
| **1** | **把「我的实现变差」当成「这个方向不行」** | 差点把「精简系统提示不可行」当结论入库 | 用户：「也有可能是你精简的不够好」|
| **2** | **跳过「看业界怎么做」直接设计实验** | 直到用户说「github 都有开源」才去看 OpenCode/Codex 源码，一看方向完全不同 | 用户：「为什么不去看看 codex claude code opencode 他们是怎么设计的」|
| **3** | **加 Profile 开关没请示**（`todo_list`/`prompt_style`）| 擅自变更产品 API 契约，全部回退 | 用户：「你加开关了？涉及产品决策时问我了吗！」|
| **4** | **`git checkout` 文件级回退**，把用户明确要求删的 middleware 又恢复了 | 构建出带 middleware 的 wheel，若不检查会污染整个实验 | 自查（核对 wheel 内容时发现）|
| **5** | **测量口径错误**：把未提交的临时状态（3,489）当成产品基准；把内层 run 的 132,008 当成模型实际输出 | 文档数字错、误判「限流没生效」 | 自查 + 合规检查 |

**共同根源**：我倾向用「能让我继续往下走」的解释收尾，而不是先验证前提。
第 1、2 条尤其危险——它们会让我把一个**实现缺陷**沉淀成**方法论结论**。

## 5. 新发现的独立缺陷

**patch 采集把编译产物带进来了**：v2 的 flipt-io r2 产出 **24.2MB patch**，其中
25,396,314 字符是 Go 编译产物 `flipt` 可执行文件（真实代码改动只有 4,344 字符）。

- 与提示词无关，是 `git diff` 采集口径问题；
- 后果：patch 体积失控、验证器可能因应用失败判负、存储浪费；
- 修法：采集时排除 untracked 的构建产物（或按 `.gitignore` 语义过滤）。
