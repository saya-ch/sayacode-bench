## 2. 关键发现（必须知道，否则会重复踩坑）

### 2.1 SAYACODE 68.8% < mini-swe/codex 86.2%（但统计不显著）

- McNemar：sayacode vs mini-swe p=0.125、vs codex p=0.250 → 均未过 Bonferroni α/3=0.0167
- **不能对外宣称"SAYACODE 更差"**，只能说方向如此、样本不足

### 2.2 "SAYACODE 改测试率 49%"是**误读**（已纠正）

- 真实数据：SAYACODE 的 patch 里**测试文件 = 0**；mini-swe **73%**、codex **42%**
- `restored-test-files.json` 表示"验证器恢复了 agent 改过的已有测试"——SAYACODE 改了但被恢复，所以最终 patch 不含测试
- mini-swe 改测试但没被恢复（改的是新增/其他测试），patch 里保留

### 2.3 SAYACODE 的真实失败模式（逐题对比得出）

| 题 | SAYACODE | 对手 | 本质 |
|---|---|---|---|
| `ansible-7e1a34` | **0B 空 patch** | mini 19KB / codex 17.8KB | 完全没改 |
| `openlibrary-fdbc0` | 1013B | mini 2867B / codex 2330B | **改得太少** |
| `NodeBB-4327a09d` | 134KB（含 Redis 数据文件 `appendonlydir/*.aof`）| mini 143KB | 范围失控 |
| `flipt-8bd3604` | 6461B（改了已有测试被恢复）| mini 11.7KB | 源码改不够，靠改测试掩盖 |

**结论**：SAYACODE 的问题是**源码修改不完整 + 偶尔空转**，不是"爱改测试"。

## 5. 坑清单（血泪教训）

1. **Docker 频繁崩溃**：主机 15.6GB 物理内存被吃满（提交 53.6GB、页面文件峰值 13.8GB），WSL 后端被压垮。缓解：关掉 ChatGPT/WorkBuddy/Edge 桌面应用（释放 ~2.4GB）、并发 ≤4–6、崩溃后 `wsl --shutdown` + 重启 Docker + `--skip-existing` 续跑。
2. **Docker 网络池耗尽**：每 trial 占 2 个网络，默认池约 17。并发 14 时 28 个网络必爆。跑前 `docker network prune -f`，并发 ≤6。
3. **阶段1 归档逻辑 bug（已修）**：原按 `reward.txt` 判断归档，阶段1 跳过验证导致所有 patch 被归档。现改为"有 reward **或** 有 patch 都不归档"。
4. **阶段1 skip-existing bug（已修）**：原只认 reward，阶段1 无 reward 导致每次重启全量重跑。现改为"有 reward 或 patch 都跳过"。
5. **PatchReplayAgent source_job 参数**：必须传**单个 trial 目录**（`jobs/<job_name>`），不是整个 jobs 目录，否则"no source patch"、全 0 分。
6. **对比脚本读错目录**：codex 的 patch 在 `jobs/`，`verify/jobs/` 只有 `replay.json`。对比 patch 大小必须读 `jobs/`。
7. **PowerShell 引号地狱**：复杂 python -c 一律写成 .py 文件再执行。
8. **进程自杀**：`Where-Object { $_.CommandLine -match 'watchdog' }` 会匹配到自己（命令行含该字符串），导致 exit 4294967295。用 `-like '*watchdog.ps1*' -and $_.ProcessId -ne $PID`。
