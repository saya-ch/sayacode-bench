# 深度分析：榨干已有四组数据（2026-11-06）

> 数据：`C:\sb\analysis\dataset.json`，**391 条 trial**
> （SAYACODE 3.2.7 / 3.2.5、mini-swe、Claude Code、OpenCode，各 40 题 × 2 重复，个别缺失）
> 关键新维度：verifier 的 `output.json` 给出**每个测试的 PASSED/FAILED**，因此可算**连续的部分得分**，不再只有 0/1。

## 1. 核心发现：0/1 口径丢掉了绝大部分信息

| group | n | 0/1 通过率 | **部分得分均值** | 中位 | 部分>0 且<1 |
|---|---:|---:|---:|---:|---:|
| SAYACODE 3.2.7 | 72 | 81.9% | **97.6%** | 100% | 12 |
| SAYACODE 3.2.5 | 73 | 84.9% | **99.2%** | 100% | 11 |
| mini-swe | 77 | 87.0% | **98.5%** | 100% | 10 |
| Claude Code | 76 | 86.8% | **97.8%** | 100% | 9 |
| OpenCode | 77 | 80.5% | **94.4%** | 100% | 13 |

**所有 agent 的部分得分都在 94–99%，但 0/1 只有 80–87%。** 差距全部来自「差 1 个测试」：

```
NodeBB-4327a09d   263/264 = 99.6%
qutebrowser-fec1  243/244 = 99.6%
element-web-772d  106/107 = 99.1%
openlibrary-ba3a   93/94  = 98.9%
```

也就是说：**这些题 agent 其实基本都做对了，只是卡在最后一个断言的边角上。**
0/1 通过率把这个「99% 对」压缩成 0，于是两组的差异被放大成噪声。

## 2. 核心发现：题库已饱和

跨 5 组统计（40 题，每题材 ≥3 次观测）：

| 指标 | 值 |
|---|---|
| **饱和题**（所有组部分得分 = 1.0） | **26 / 40 = 65%** |
| 死题（所有组 = 0） | **0** |
| 中间难度 | 14 / 40 |
| 题级部分得分均值 | **97.6%** |
| 有区分度（跨组 sd > 0.02）的题 | **仅 8 / 40** |

区分度最大的题（sd 高才能拉开差距）：

| 题 | 均值 | sd |
|---|---:|---:|
| `navidrome-dfa453cc` | 60.0% | 49.0 |
| `ansible-de5858f48` | 89.0% | 25.5 |
| `openlibrary-03095f26` | 93.3% | 13.3 |
| `navidrome-812dc209` | 96.7% | 10.0 |
| `element-web-d4051600` | 97.1% | 7.0 |

**这解释了为什么四组两两配对全部不显著**：40 题里 26 题对谁都是满分，
真正能区分的只有 8 题，样本量根本不够。继续在 40 题上加重复也救不回来 —— 那是给饱和题加重复。

## 3. 核心发现：2 题是「环境性不可过」，对所有 agent 同样失败

| 题 | 失败测试 | 失败次数 |
|---|---|---|
| `qutebrowser-fec187c2` | `test_safe_display_string[url5-(unparseable URL!) http://www.арріе.com]` | **10 / 10** |
| `tutanota-51818218` | `DesktopDownloadManagerTest::downloadNative, no error` | **9 / 9** |

- qutebrowser 那题 244 个测试只挂这 1 个，是 IDN（西里尔字母同形域名）在容器里的解析行为差异；
- tutanota 那题 4 个测试里挂 1 个，是 Electron 下载管理器在无网络沙箱里的环境依赖。

**这两题不反映 agent 能力，应从对比中排除**（占题集 5%，对所有组同等扣分，会稀释区分度）。
它们的 `stable_fail` 特征也说明：**「稳定失败同一测试」是识别坏题的有效信号**。

## 4. 核心发现：同题重复本身就是噪声源

同题 r1/r2 一致性（每组）：

| group | 配对题 | 稳定通过 | 稳定失败(同集合) | **随机翻转** | 不稳定失败 |
|---|---:|---:|---:|---:|---:|
| SAYACODE 3.2.7 | 37 | 28 | 3 | **5** | 1 |
| SAYACODE 3.2.5 | 37 | 31 | 2 | **2** | 2 |
| mini-swe | 38 | 32 | 2 | **3** | 1 |
| Claude Code | 39 | 31 | 2 | **5** | 1 |
| OpenCode | 40 | 29 | 4 | **7** | 0 |

**每组有 2–7 题在两次重复间翻转**（一次过、一次不过）。之前发现的「element-web r1/r2 镜像反转」
（`772df302`、`d405160080`、`qutebrowser-c09e1439f`）就是这类。

在 40 题规模下，翻转题数（2–7）已经和任何两组之间的真实差异同量级 ——
**单次对比测到的 −2.6pp 完全可能是翻转噪声的排列组合**。

## 5. 核心发现：改得多的 patch 反而更容易过

| patch 特征 | n | 部分得分均值 |
|---|---:|---:|
| patch > 5KB | 90 | **97.4%** |
| patch ≤ 5KB | 62 | 94.1% |
| 改 ≥3 个文件 | 83 | **98.2%** |
| 改 <3 个文件 | 69 | 93.5% |

不是「改得多所以错得多」，而是**需要大改的题本身描述清晰、改对了就过**；
小改题往往是边角断言，容易差一个测试。

## 6. 对「换题库」的直接指导

1. **必须换**：65% 饱和 + 只有 8 题有区分度，40 题这套在四组对比上已经到分辨力上限。
2. **换的判据要写进选题器**：
   - 排除「所有 agent 稳定失败同一测试」的题（用本次的 `stable_fail` 检测即可，跑 2 个 agent × 2 重复就能筛出来）；
   - 优先「跨组部分得分 sd 大」的题，而不是只看 0/1；
   - 控制「部分得分 99% 但 0/1 为 0」的比例 —— 它们只贡献噪声。
3. **报告口径升级**：以后同时报 `0/1 通过率` 与 **`部分得分`**（连续），后者对小样本对比敏感得多。
