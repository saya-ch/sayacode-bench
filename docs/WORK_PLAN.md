# 公开基准评测与调优执行计划

开始日期：2026-10-22。研究模型统一记为 DeepSeek-V4.1-Flash；接口是连接元数据，不是研究对照因素。

## 交付与阶段门槛

1. 固定生产 wheel、依赖锁、Harbor 0.24.0、公开数据源码和镜像身份。原始数据和密钥留在仓库外。
2. 官方参考解、空解、网络探针与超时清理通过后，运行少量开发校准题，测量服务稳定性和资源消耗。
3. 在查看正式成绩之前冻结开发和最终验收划分、预算、配置、对照顺序以及排除规则。旧 32 题仅作已见回归集。
4. 在开发集完成基线与最多两个候选的真实比较，记录错误、假设和改动；按预定规则选择，冻结候选身份。
5. 在独立最终验收任务上进行配对重复，原始失败保留；SWE-bench Pro 每个 trial 的补丁均在干净镜像重判。
6. 输出任务块统计、区间、用量覆盖率、服务错误与机制实际触发信息，完成代码审查、门禁和可复现说明。

任何阶段若外部资源不可用，保留明确的中止记录和剩余工作；不能以模拟数据或基础设施测试替代真实评测完成。

## 当前下一步

WSL 3.0.3 升级后的固定八次诊断已完成，就绪未通过，本轮本地平台配置试验结束。后续准备私有执行仓库的两题真实生产校准，详见 [云端校准](cloud-calibration.md)。未上传模型密钥、未 dispatch；历史付费探针用量覆盖和 GitHub Actions 额度仍待核实。

两题校准通过运行链路门禁后，正式研究仍需独立完成：冻结全局 schedule、按任务与重复的配对块分片、共享费用账本、源与 pristine 实际资源核验，以及跨片严格归并和缺失／重复检查。不存在把两题校准晋升为 48 次开发或 96 次最终比较的路径。正式模型试验开始前再冻结相应实现身份和协议修订。

## 架构

- Harbor 承担任务环境、资源和超时、任务执行与官方验证器。
- SAYACODE 仍运行现有应用、LangChain / LangGraph、工具和子任务；不另写 Agent 循环。
- 本仓库只承担源身份与选样、产品薄适配、实验清单、官方结果的只读分析。
- SWE-bench Pro V2 是主要编程基准；Terminal-Bench 2.1 固定历史版本作为终端能力补充，结果分开。
- 不把两种基准和旧自构造集合成一个总分，也不把 Linux 容器成绩扩展为原生 Windows 成绩。

详细研究协议在 `protocol.md`，实际冻结规模与候选身份以 studies 中的清单为准。
