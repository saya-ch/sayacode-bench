## 固定次数的无模型复核

在查看正式模型成绩之前，另行固定执行了同补丁三次 pristine replay 与官方参考解三次新环境验证，共六次，没有运行到通过为止。六次均得到 reward=0；此前相同任务的参考解门禁曾得到 1。参考解也出现 pytest／AST 等测试基础设施内部异常，因而不能将该现象直接归因于 SAYACODE 的补丁。完整聚合在 `reports/calibration-qutebrowser-stability-v1/aggregate.json`，原始首判未改。

这提供了本机该 fixture 不可靠的实际证据，但不足以锁定底层依赖、虚拟化或硬件的唯一根因。正式选样需要额外资格检查；通过有限次数的检查也不证明测试永不波动。

公开白名单事实、原始工件哈希及带中止标志的分析在 `reports/calibration-qutebrowser-v1/`。完整轨迹、检查点与验证输出保存在仓库外，未公开原始思考内容或私有连接。

首批原清单未包含公开 profile 字段。补充文件 `input-identity-supplement.json` 从该批运行开始时已归档的 identity 元数据核对参数，并绑定原 identity SHA；不是读取后来可能变化的私有连接补造事前配置。该批实际为 65,536 上下文预算、8,192 最大输出、0.8 摘要比例、保留 12 条消息、上下文编辑关闭、模型重试 1、工具重试 2。未显式配置的采样参数按服务端默认，无法独立证明模型权重版本。

## 实际资源限制

本机 Linux Docker 容器检查：

- CPU 为 1，`cpu.max=100000 100000`；内存硬上限 4 GiB。
- Docker 还允许 4 GiB swap；不能将它描述成总共只有 4 GiB 可用内存。
- 官方 `storage_mb=10240` 被保留在任务元数据，但 Harbor 的 Docker 实现没有对应磁盘硬配额。仅有宿主空闲空间门禁。
- 阶段网络使用本仓库固定 nginx 网关和 Docker 内部网络，真实隔离探针通过；不是 Harbor Modal 官方环境。
- 本地回调统计不包含 SDK 或代理的所有 HTTP 尝试；生产模型重试和 SDK 重试可能叠加。

这些差异需要随正式结果同时发布，不能把本机子集成绩写成官方完整排行榜成绩。

## 后续冻结

第二个独立校准批次用于完成另一题并核验完整运行资源。未执行的 v2 草案在首次调用前因基础设施完善而封存，实际运行使用 `calibration-ansible-v3.json`；实际实现身份保存在该批运行的 identity.json。正式清单只依据资源、任务元数据与预先规定的评分门禁决定，不依据任务难易或 Agent 得分挑题。尚未运行的任务保持未执行，不能当作失败或成功。

Ansible 第二校准已结束：62 次原生模型回调，用量全部报告；输入 1,784,623、输出 36,489 tokens；原环境总耗时 594.97 秒，独立重判另用 43.94 秒。两层 reward 均为 0，干净环境测试 49 通过、10 失败，源与重判实际镜像和平台相同。该批完整执行，无模型连接故障、无子任务；它仍只是资源和诊断校准，不是最终成功率样本。

基于这些校准，正式对照保留 8 个开发任务、24 个最终任务作为目标，均先经过固定环境资格流程；不以两道 smoke 代替完整研究。初始候选清单和原 seed 已公开，最终环境资格名单及正式重复数／预算仍需在首次正式模型执行前冻结。候选假设与修订来源见 [hypotheses.md](hypotheses.md)。
