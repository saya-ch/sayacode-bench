# 预声明的统计补充与仓库簇敏感性

`scripts/analyze_sensitivity.py` 只读取冻结清单的公开任务／仓库元数据与逐次结果。它复用 `study.phase_summary` 内的 `analyze_experiment` 验证成绩、重复覆盖和配对，也继承已有费用证据的正式资格检查。不读取题面、参考补丁、隐藏测试、工具正文或模型思考，不建立新的评分器，也不调用模型。

主分析仍是预注册的任务宏平均与配对任务 bootstrap。这个脚本补充绝对成功率区间和仓库相关性的敏感性检查；不能根据哪个区间显著或更好看，事后替换主分析。

## 在首次正式模型执行前冻结

```powershell
python scripts/analyze_sensitivity.py --freeze-protocol `
  --output C:/evaluation-results/sensitivity-protocol-v1.json
```

协议记录脚本、主分析、资格验证与预算模块的 SHA256，以及抽样单位。此命令不需要成绩文件。正式清单应引用该协议文件及其哈希，首次正式模型任务必须晚于协议冻结。修改脚本或其验证依赖后是新的统计身份，不能覆盖旧协议，或者查看成绩后悄悄换方法。

CLI 固定 `seed=20261022`、`samples=10000`，没有选择其他参数的入口。函数中的仓库 bootstrap 辅助参数仅用于已知分布的人工测试，不是正式分析可调开关。软件版本和执行源码也应与正式运行归档一并保留。

## 一题先归约为一个观察值

对配置 c、任务 i，计划重复数为 R：

```text
p[c,i] = 该配置该题 R 次端到端成功次数 / R
绝对成功率 = 所有 N 道任务的 p[c,i] 的算术平均
d[i] = p[candidate,i] - p[baseline,i]
```

任务级成功事实来自现有公开结果验证。失败仍计入分母，未知不会补为失败或成功，未跑的重复不会被丢弃。完整一题才有完整的 `p[c,i]`。

24 道任务每题运行 3 次，仍是 24 个任务块；72 次调用不是 72 个独立任务。重复有助于观察同一题的随机性，但不会自动增加任务分布覆盖或仓库数量。

## 每配置的绝对成功率 95% 区间

对每个配置，从 N 个任务均值中有放回抽 N 个，计算均值，重复 10000 次。使用 2.5% 和 97.5% 线性插值分位数。实现复用已有 `paired_bootstrap` 的均值抽样运算，对非负的任务成功率同样成立；输出方法名明确为绝对成功率，避免将它误称为配置差值。

完整单配置 `validation` 也可以获得这个绝对成功率区间。它不是基线与自身的伪配对；没有 candidate 时，不输出配对差值敏感性。

小于两道任务不生成区间。全成或全败时，经验 bootstrap 可能给出零宽区间；这只反映观察样本中缺少变异，不能解读为总体真实成功概率已确定。

## 每仓库宏平均

每个配置分别报告各仓库的任务宏平均，包含该仓库的计划任务数和完整任务数。任务未完成时，完整分母下的仓库宏平均保持 null；可以另外展示已完成任务的描述均值，但必须显示其覆盖数。

仓库名称和任务映射只来自 manifest，不能通过题目正文、答案难度或模型分数重新分簇。

## 配对差值的仓库簇 bootstrap

同一仓库内的任务可能相关。敏感性分析以整个仓库为簇：有 J 个仓库时，每次有放回抽 J 个仓库，保留每个抽中仓库的全部任务以及已经按重复归约的任务均值。仓库抽中两次，其全部任务也出现两次。

每次估计：

```text
delta* = 抽中的所有任务 d[i] 之和 / 抽中的实际任务数
```

因为仓库大小不同，每次分母可能不同。不能先把每个仓库变成一个均值，再将它们等权平均，却把该结果冒充任务宏平均。

脚本另行报告：

```text
repo_equal_delta = 各仓库内部 d[i] 均值的等权平均
```

它回答“平均一个仓库怎样”，与主分析的“平均一道任务怎样”目标不同。两种点估计和各仓库差值并列保留，不选择更有利的一种。

J < 2 时不生成仓库簇区间。即使有 11 个仓库，簇数仍然很少；百分位簇 bootstrap 只是敏感性观察，不能保证小簇数下的精确覆盖率，更不能独立证明生产泛化。

任务数与仓库数始终按实际 manifest 输出，不写死 24 或 11。Terminal-Bench 若没有自然项目仓库映射、所有任务只标成同一基准来源，就不能凭类别重新编造仓库簇；此时不生成仓库簇区间，保留任务级绝对区间及该限制。

## 不能把小样本包装成细微收益

24 道任务不足以支持可靠的 2–5 个百分点收益宣称。一个单次任务的成功与失败就约相差 4.17 个百分点；重复后虽能得到更细的数值刻度，独立任务数仍没有增加。以成功率约一半、24 个独立二元任务作量级参照，标准误约 10 个百分点；这不是本实验的正式区间或精确功效结论，只说明样本规模的限制。

配对相关性可能降低差值方差，具体功效仍取决于实际变异和任务分布，不能把上述量级说成所有情况下都无法检出差异的数学定理。应报告效应大小与区间，避免将“不显著”解释成等价，也避免将小样本中偶然很窄的区间解释成已证明微小改进。

## 资格与使用

```powershell
python scripts/analyze_sensitivity.py --manifest frozen-study.json `
  --records C:/evaluation-results/study/records.jsonl `
  --output C:/evaluation-results/study/sensitivity.json
```

输出文件拒绝覆盖。CLI 继承结果目录的 `abort.json`、`invalid.json`，并保留输入内容哈希；不导出输入文件的本机绝对路径或逐条原始内容。

完整且满足既有最终资格的 `holdout/validation` 才能获得正式区间。缺任务、缺重复、未知结果、无效证据、配对连接不一致、开发或校准阶段均只输出 `descriptive_ineligible`，区间为 null。描述值不能冒充完整任务分母上的正式成绩。

统计脚本验证的是提供材料的已声明资格，不能替代独立环境门禁、执行真实性检查、训练污染审计或任务代表性论证。必须同时公开主结果与这份预声明敏感性结果，不能按结论选择性发布。
