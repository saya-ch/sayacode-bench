# 新轮次执行协议 v13

本执行合同用于安装阶段故障之后重新冻结的 `restart-v2` 研究轮次。它补充完整安装预检和先导费用延续；[v12 统计协议](../studies/sensitivity-protocol-v12.json)的候选规则、抽样、重复数和敏感性分析保持原字节。新合同在 [execution-protocol-v13.json](../studies/execution-protocol-v13.json) 中绑定原统计协议的 SHA256。

原分析身份同时包含旧执行代码的 SHA，不能要求它与新源码的完整身份相等。旧文件永久保留；`inputs/restart-v2/analysis-protocol.json` 单独冻结新源码的真实完整身份。统计脚本、分析、有效性、计价、资源规则的代码 SHA 以及抽样次数、seed 和抽样单位必须仍与原方法一致。最终分析的 `--protocol` 使用新文件，不能给旧记录补新身份。

## 先导与正式样本

先导源码、master、三个已完成样本、一个安装失败样本及尚未执行的计划均永久保留。先导不完整，不能用于候选签收或声称完整基准成绩。新的开发研究完整执行八任务、三个原配置、每配置两次；不拼接先导成绩、补丁、会话或检查点。

新轮次具有独立的 source、implementation、master、plan 和 trial 身份。沿用原工作根仅为保全原始证据中的绝对路径；新输入追加在 `inputs/restart-v2/`，计划使用 `primary-dev-v2-plan.json`。最终阶段和 Terminal 阶段同样使用新轮次的输入及计划，不覆盖原先导文件。

## 安装预检

固定三十二个 SWE 镜像和十四个 Terminal 镜像全部运行 Harbor 原生 `install_only=True`。保留不可变镜像 digest、官方资源、原始 JobResult／TrialResult、安装日志、严格的实际 Agent 用户启动检查和清理记录。预检不提供供应商凭据，不进入 Agent 执行或 verifier，不读取评分来筛选镜像。

安装先通过官方依赖入口保证 curl 可用，再以正常 TLS 校验下载固定 uv 安装脚本；仅证书验证或证书文件错误才触发官方证书安装入口。HTTP、DNS 或超时错误不伪装为缺证书。安装预检通过仅说明当时的安装和启动可用，未来依赖服务故障仍应停止并留证。

托管矩阵每组最多顺序执行两个独立 Harbor Job，完整范围仍是四十六个 case；两项不共享容器或 Agent 状态。这样只需二十三份分组归档，减少同一输入的重复下载及服务元数据请求。传输使用同一完整 tar 的单分片，原多分片及失败版本继续保留。实际任务的构建和安装超时不缩短；两个 SWE 最坏构建加安装合计九十分钟，托管 job 上限一百二十分钟，留三十分钟准备与收尾。

启动矩阵前读取 GitHub 实际响应头的 API 余量。完整预检要求至少九百五十次余量，单项或双项回归要求至少一百次。余量不足时仅保存原始配额及重置时间，不启动安装；操作端在窗口重置后使用新的不可变引用，不能把未启动记成安装通过。Actions 交接固定为 `evidence/` 及可选的压缩备用归档，合并按真实目录读取，每个 case 的原始绝对路径与 SHA 保留。

## 费用适用性与累计预算

`pilot-carry.json` 是严格的原件证明，不是账单核销或人工豁免。验证器重开固定先导记录、ledger、原始阶段和异常、代码来源及真实用量旁证。它要求所有先导记录均被覆盖，三个已核模型记录的投影与原始行逐字节相同。

只有正面原生阶段及固定代码证据证明失败早于 `adapter.run` 时，才判定该尝试的模型计量不适用；缺 worker 或空 usage 本身不够。原用量、原账单字段和原失败状态保持不变，不补造测得零 tokens 或零账单。进入模型执行后的未知用量仍严格阻止新付费派发。

新研究沿用同一个一百元预算、百分之八十派发停止阈值及原预算起点。先导真实模型消耗和既有历史结算继续累计，历史结算只计一次。开发、主最终及 Terminal 的原会计记录全部延续，由既有计价模块按真实 source／request 身份去重。计价模块和原 v3 价格快照不因重启而改写。

## 前置条件与证据变化

CLI 冻结同时接收 `--execution-protocol`、`--analysis-protocol`、`--installation-preflight`、`--pilot-carry`，缺一不可。新开发阶段禁止额外传入旧开发结果；先导只通过费用投影进入 `prior_records`。最终阶段继承同一协议、预检和费用收据。

冻结、计划装配、恢复、模型运行前和每个任务派发边界均重验对应证据。原件丢失、SHA 改变、模型用量覆盖不足或累计预算停止时，不得继续派发，也不能重建空账本、覆盖失败或缩小分母。
