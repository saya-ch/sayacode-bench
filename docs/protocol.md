# SAYACODE 公开任务评估与调优预注册

日期：2026-10-22。状态：**资源校准前的预注册骨架，尚未冻结最终试验任务、次数或候选**。

本文固定实验的原则、候选选择和分析方法。正式验收开始前，必须补齐并冻结机器可读 manifest；仅有本文不构成正式实验已经启动或完成的证据。具体数量依据资源校准确定，不预先承诺本机与接口无法承受的规模，也不能在查看最终成绩后减少样本。

## 研究问题与证据范围

主要问题是：同一规范模型、基础工具、资源和预算下，一项在开发集选定的 SAYACODE 改进，是否改变公开编程任务的端到端完成率？质量、耗时和报告用量分别汇总。

基准成绩不独立证明规划、多 Agent、记忆或摘要的机制收益。只有实际触发并单独控制这些机制时，才讨论其对应影响。运行器、自检、CI 和容器启动是工程验证，不是模型效果证据。

不以新方法必须优于基线作为完成条件。真实执行、负结果、错误解释和独立验收都是交付的一部分。公开任务可能已经出现在模型训练中，不能声称完全没有污染。

### 选样与封存

1. 下载并记录任务文件、数据 revision、镜像摘要和官方执行器版本。
2. 在看 Agent 成绩前声明资源上限、架构和语言范围；按公开元数据排除本机确实无法运行的任务，保留全部排除原因。
3. 用固定 seed 按仓库或类别分层抽样；开发与最终验收不重复，条件允许时按仓库隔离。
4. 校准仅使用开发任务。根据磁盘、内存、运行时间与报告 token 确定正式规模，并冻结选样脚本、seed、完整候选池、任务 ID、文件哈希与计划执行顺序。
5. 候选锁定前，不使用最终验收的参考补丁、隐藏测试、验证日志或成绩指导产品修改。不得先运行再挑容易题。
6. 冻结后新增异常题不能静默删除。保留原记录，按预先规定的整批修订或替补规则处理；修订后是新的实验身份。

子集报告必须注明基准版本、N 道任务和选择范围，不写成完整排行榜成绩。

### Terminal-Bench 预声明范围

终端补充研究拟覆盖六类：`software-engineering`、`debugging`、`system-administration`、`file-operations`、`data-processing`、`security`。单题官方内存不超过 4096 MB，官方 Agent 时间预算不超过 1800 秒，单并发、无 GPU、无自定义 Compose。这里是在看模型成绩前限定研究适用范围，不把所有终端任务改成统一资源或统一超时。

`select_tasks` 的 `categories` 与 `max_agent_timeout_sec` 默认均为 None；未声明时，既有选样行为保持。声明后，类别不适用使用 `outside_predeclared_category_scope`，官方时间超过上限使用 `official_agent_timeout_exceeds_study_scope`，官方时间未知或无效则单独记录 `missing_or_invalid_official_agent_timeout`。`rules` 记录过滤器，`catalog_sha256` 仍覆盖完整原始候选池，不能以过滤后的小池冒充完整数据集身份。

只读取公共元数据即可准备 2 道环境校准候选及 12 道最终候选：

```powershell
sayacode-bench prepare --benchmark terminal-bench-2.1 --cache C:/evaluation-cache `
  --dev 2 --holdout 12 --seed sayacode-tb-20261022-scope-v1 `
  --category software-engineering --category debugging --category system-administration `
  --category file-operations --category data-processing --category security `
  --max-agent-timeout-sec 1800 --output terminal-candidates.json
```

此处 `dev` 用于保存校准候选，`holdout` 保存未使用的最终候选；这一步不签收模型调优候选、不运行模型，也不读取题面正文、参考解或隐藏断言。正式使用前仍需完成环境／评分器校准，并冻结实际研究清单。校准组需明确排除在正式最终集之外，可以重复传入 `--exclude-leakage-group`。所有选中任务原始 `agent`、`verifier` 和 `environment` 配置保持原值。

## 模型、连接与运行条件

规范模型身份为 `DeepSeek-V4.1-Flash`。允许使用用户授权的本机反代和硅基流动连接；路由实际模型 ID 与规范模型映射单独记录，不将两个连接当作提供商优劣比较。

- 尽量让同一个任务与重复编号的基线、候选使用相同连接。连接切换允许发生，但必须记录原因、时间、受影响任务与模型配置。
- 不输出密钥。公开记录只使用连接别名，例如 `local_proxy`、`siliconflow`，不包含带凭据 URL。
- 同一配对内跨连接时，保留成绩并标记；主程序不将其直接视为无条件可比。需要按声明规则重做整对，原始记录仍保留。
- 模型名称与接口字段不能证明上游权重完全相同，报告明确这一限制。
- 上下文窗口、输出预算、采样参数、摘要、记忆、Skill、工具集合和重试层次均固定并记录。未配置或服务未报告的字段写未知。

本机初始条件为 Docker 可用内存约 8 GB、可用磁盘约 95 GB；这不是所有官方任务的统一资源需求。先并发 1，遵守任务声明的 CPU、内存、磁盘和官方时间预算。资源不满足的任务在选样阶段显式处理，不能运行时偷偷降低资源再宣称官方可比。

若修改官方资源、时间、网络或验证协议，逐项列为偏离，并限制可比性声明。SWE-bench Pro 的严格协议包含独立 pristine 镜像重放；Terminal-Bench 的环境与工件按其官方验证方式处理，不强行以同一补丁形式替代全部任务交付。

## 开发与真实调优

主对照为基线与至多两个预先命名开发候选。每个候选记录：错误样本、失败机制假设、单项改动、预期指标、源码身份以及不应变化的行为。

候选可以来自提示、工具描述或现有官方中间件配置，但不另造 Agent 执行框架。不同时换模型、工具、摘要与分工后把结果归因到单一机制。

开发选择顺序固定为：

1. 开发集任务宏平均成功率较高者优先。
2. 成功率相同时，仅在所有并列配置的报告用量均完整时，选择总报告 token 较少者。
3. 仍相同或用量不足以比较时，优先基线；基线不在并列候选内时，按预注册候选顺序选择。
4. 开发任务缺失、成绩未知、模型或配对连接不一致时，不自动选出候选。

选择后冻结唯一候选源码、配置和哈希，再开始最终验收。开发集表现不作为最终泛化成绩。没有候选胜出时保留基线，并如实报告未获得改善。

保留基线时，最终阶段使用 `phase=validation`、仅一个基线配置、`candidate=null`。这是一组独立未见任务上的最终验收，报告绝对成功率与资源，不构造基线与自身的伪配对，不生成机制差值或配对区间。选中不同候选时，`phase=holdout` 仍严格使用基线与唯一候选两个配置。

`lock_candidate(dev_manifest_path, records_path, variant_paths, output_path)` 在完整开发试验结束后保存不可覆盖的签收单，包括原始开发清单、记录哈希、任务 ID／修复组、生产 wheel、依赖和全部候选配置身份及确定性选择结果。中止、失效、未收尾、缺结果或未知成绩的开发批次不能签收。

冻结最终清单前，`validate_candidate_receipt(receipt_path, final_manifest, variant_paths=...)` 重读开发来源并核对选择，检查最终生产 wheel／依赖／所选配置与开发相同，拒绝任务 ID 或同修复组跨集重叠，并强制选择对应的 holdout／validation 阶段。实际配置文件字节也需一致。签收单用于防止误改和事后换候选，不是第三方认证或数字签名。

## 评分器校准和独立验收

复用官方 harness、容器和验证器。Agent 使用生产 SAYACODE 与原生 LangChain / LangGraph 执行链，只增加安装、传题、配置和观测的薄适配。

模型运行前，先检查参考解应通过、空解应按官方预期失败；记录环境异常。Agent 环境不挂参考解与隐藏评分材料。

校准后增加的固定本地资格规则见 [fixture-gates.md](fixture-gates.md)：每个候选三次参考解全部通过且一次空解失败，实际镜像／平台与资源一致。整修复组排除与原 seed 的机械替补在正式模型前完成；最终结果明确是环境资格子集。资格镜像身份进入冻结清单，真实模型与重判逐次核对，tag 同名不代替一致性证据。

SWE-bench Pro 保存实际交付补丁，在全新官方镜像中应用并重新判分，主报重放结果，并保留原环境结果、应用失败、验证失败和日志身份。若使用的运行方式未实现这一条件，则该批不能标为严格协议成绩。

不能只以退出码、Agent 自称完成、官方 reward 文件存在或日志关键词判定成功。规范化结果必须指向实际官方验证证据。代码理解等人工语义判断单独处理，不能混入自动编程通过率。

## 配对、重复和预算

正式 manifest 冻结每道任务、配置和重复编号。一个 `task × repeat` 构成一个配对块；以固定 seed 决定 AB 或 BA 顺序，交错执行，减少时间段服务波动的影响。每次使用新会话、状态和工作区，不共享开发记忆或前次答案。

不对产品工具和模型轮次添加人为上限。实验采用任务外部墙钟预算、整批已报告 token 的停止新派发阈值，以及容器生命周期管理。callback 的 usage 不能覆盖缺失用量、在途调用及 SDK／代理内部尝试，因此报告 token 阈值不是严格费用保证。

正式任务数、重复次数、候选配置数、墙钟预算与整批阈值在资源校准后填入 manifest。未完成全部计划，不得改小计划分母或宣布最终比较完成。

### 外部故障止损

- 401／403／429 停止当前批次新派发，保存原因。只有已授权且确认模型配置一致的备用连接可以按预先规则继续，不自动购买额度。
- 最近 5 次启动试验中出现至少 2 次终态连接类失败，暂停诊断；不能拿基础设施错误当提示调优依据。
- 强制停止清理本实验拥有的容器，清理失败也保存已有记录。
- 缺失或未开始任务标为未执行，不能造作模型失败。
- 故障修复后如复验，重做受影响的完整配对块，保留旧块。原始端到端表现与稳定条件下的复验分表，不只补失败侧覆盖旧分。

## 主指标与分析规则

成功率先对每题重复求均值，再对任务求均值。主要效应为 `候选任务均值 − 基线任务均值`。计划但未执行、结果未知、未确认验证的成功与缺配对均阻止正式比较；已启动后确实失败的试验保留在端到端分母。

95% 区间使用固定 seed 的 percentile 任务块 bootstrap，重复试验跟随其任务一起抽样。重复次数不增加独立任务数。任务数不足 2 不生成区间；同仓库相关性、小样本和任务选择限制外推。若开展仓库簇敏感性分析，另行报告，不以最有利区间替换主结果。

同时报告所有状态、未知、未执行、配对完成数、每题差值、耗时中位数／P95、报告 token 与覆盖率、实际子任务数和摘要触发。失败消耗不删除。没有可靠计价时费用写未知。

完整性标志不证明统计功效或因果有效。bootstrap 区间跨零时写证据不足，不写“已经证明提升”；即使不跨零，也限制到所选任务、模型、资源和版本。

## 规范化统计接口

`analyze_experiment(manifest, records, bootstrap_samples=10000, seed=20261022)` 不重判任务，只接受已核验外部结果。CLI：

```powershell
python -m sayacode_bench.analysis --manifest <冻结清单.json> --records <逐次结果.jsonl> --output <分析结果.json>
```

manifest 必填：`phase`（`calibration/dev/holdout/validation`）、`frozen`、`canonical_model`、`configurations`、`baseline`、`candidate`（开发和单组 validation 阶段可空）、`repeats`、`tasks`（每项包含 `task_id/repository`；候选封存还需要 `leakage_group`）。`validity_issues` 记录配额中断、协议偏离或其他失效条件。`formal_comparison_eligible` 只用于双组 holdout，`formal_validation_eligible` 只用于完整单组最终验收；任一缺失或未知都使相应标志为 false。

逐次结果必填：`task_id/configuration/repeat/status/success/verified/canonical_model/endpoint`。`repeat` 从 1 开始，`success` 为布尔值或 null；成功且状态完成仍需 `verified=true`，表示适用的官方验证和独立重放已经核实。运行失败可用 `success=false, verified=false` 记录端到端失败；运行完成但缺验证的结果保持未知。

可选资源字段为 `duration_seconds/input_tokens/output_tokens/usage_complete`。`usage_complete` 仅在该试验所有应计量调用的用量完整时为 true，不根据部分数值猜测完整。连接字段只放别名。源码、镜像、原始结果路径和哈希另由 manifest 与证据目录保存；统计模块不加载密钥和完整 HTTP 内容。

## 最终交付与尚待冻结项

交付包括选样与环境清单、评分器正负例、自检与真实调用边界、开发错误分析、候选选择记录、最终锁定源码、所有逐次结果、独立验证证据和汇总。发布前检查凭据、用户路径和第三方许可。

正式验收前仍需填定：

- 开发／验收任务 ID、选样 seed 和数据哈希。
- 校准耗时、磁盘、模型用量和服务稳定性。
- 正式 N、重复次数、预算、连接切换与故障恢复规则。
- 基线与候选源码、配置身份及唯一候选选择记录。
- 官方镜像资源、网络策略、harness 版本和协议偏离。
- 分析源码身份、原始证据位置和最终封存时间。

这些字段未补齐并冻结时，不运行最终 holdout，不将开发或基础设施调试包装为最终研究成绩。
