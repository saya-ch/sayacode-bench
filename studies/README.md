# 研究配置与冻结时序

三个初始配置使用相同模型、图、工具、摘要、权限和团队能力，只改变追加的执行指导。

| 配置 | 假设 | 状态 |
| --- | --- | --- |
| baseline | 当前产品作为对照 | 已执行独立资源校准；正式开发与最终验收未开始 |
| diagnostic | 显式需求证据与失败诊断可减少错误方向上的修改 | 待开发集验证，未选中 |
| focused | 聚焦接口和测试可降低重复调查与叙述开销 | 待开发集验证，未选中 |

这些是假设性候选，不是已经证明有效的调优。`calibration.json` 是固定种子选出的两道资源校准题，不是正式验收清单。

资源与接口校准后才冻结正式开发与最终验收名单。真实开发错误、候选比较和选择结果必须另行保存；不得使用最终验收结果倒推候选指令。追加指导仍走现有生产应用，官方原始题面不改写。

最终候选通过 `lock-candidate` 签收。基线胜出时最终使用单组 validation，不构造基线与自身的伪对照。

正式分析使用最新的 `sensitivity-protocol-v6.json`：任务块主分析、仓库簇敏感性、10,000 次抽样及 seed 不变，新增绑定资源核验规则，并更新阶段校验及离线正式资格的源码身份。源试验、pristine 与冻结资格都必须符合官方声明及实际 Docker／cgroup 限制；缺失策略不能获得正式资格。旧版文件保留为正式模型运行之前的协议修订历史；它们没有对应正式效果试验，也不能从中选择更有利的结果。
