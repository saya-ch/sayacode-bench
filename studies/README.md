# 研究配置与冻结时序

三个初始配置使用相同模型、图、工具、摘要、权限和团队能力，只改变追加的执行指导。

| 配置 | 假设 | 状态 |
| --- | --- | --- |
| baseline | 当前产品作为对照 | 已执行独立资源校准；正式开发与最终验收未开始 |
| diagnostic | 显式需求证据与失败诊断可减少错误方向上的修改 | 待开发集验证，未选中 |
| focused | 聚焦接口和测试可降低重复调查与叙述开销 | 待开发集验证，未选中 |

这些是假设性候选，不是已经证明有效的调优。`calibration.json` 是固定种子选出的两道资源校准题，不是正式验收清单。

资源与接口校准后才冻结正式开发与最终验收名单。真实开发错误、候选比较和选择结果必须另行保存；不得使用最终验收结果倒推候选指令。追加指导仍走现有生产应用，官方原始题面不改写。

最终候选通过 `lock-candidate` 签收。基线胜出时最终使用单组 validation，不构造基线与自身的伪对照。

当前正式分析入口使用 `sensitivity-protocol-v10.json`：任务块主分析、仓库簇敏感性、10,000 次抽样及 seed 不变，同时绑定资源核验、分片与恢复、费用、资格检查及 Terminal 选择清单的实现身份。离线报告会校验冻结实现，敏感性分析还须显式传入冻结协议；金融证据校验与标准报告入口一致。源试验、pristine 与冻结资格都必须符合官方声明及实际 Docker／cgroup 限制；缺失策略不能获得正式资格。旧版文件保留为正式模型运行之前的协议修订历史；它们没有对应正式效果试验，也不能从中选择更有利的结果。

资格检查使用的源码版本与未来模型运行的源码版本分别记录。SWE 已启动的 v7 资格链保持原版本；Terminal 的 v1 清单发生跨平台目录身份错误，尚未执行控制即退出，v2 清单保留相同任务和抽样规则并修正目录哈希。冻结模型阶段时不能覆盖这些历史字段。Terminal 补充阶段只使用 SWE 开发阶段签收的配置，不根据 Terminal 成绩重新选择候选。
